# 首次调用提问脚本

本文件定义本 skill 在**当前对话首次调用任意子指令**时的 onboarding。它是入口协议，不是一个图片模板。一次对话只执行一次；若用户选择已有类型，继续对应制作；若用户选择新建类型，先完成需求收集。

若用户明确要无字底图，按 background-only 模式承接，主题与平台已清楚时直接制作；不要求标题、Logo 或完整封面类型确认。静图 / 动图是同一配图项目的呈现方式，不是内容类型；已明确主题与动效需求时沿用信息，不要求再从独立动画模式菜单选择。完整封面会同时保留纯底图与可编辑项目，见 [资产模型](asset-model.md)。

## 宿主工具适配

`AskUserQuestions` 是旧版文档中的概念名称，不是本 skill 注册的工具。根据当前会话的工具列表、工具说明和运行模式决定实际交互方式，不能从文档中的名称推断工具已存在。

| 运行环境 | 使用方式 |
| --- | --- |
| Codex 提供 `request_user_input`，且当前模式与提问目的符合调用约定 | 使用当前工具的真实名称空间和参数，例如 `functions.request_user_input`；按下面的 JSON 示例构造参数 |
| Codex 中工具不可用、注明仅 Plan 模式而当前是 Default，或当前提问不满足其使用条件 | 直接用普通中文问句完成同一次引导；不切换模式、不伪造选择卡片 |
| ChatGPT 提供原生或连接器的结构化问答工具 | 读取该工具实际 schema 后调用，保留同样的能力说明与类型语义；不套用 Codex 参数给另一个工具 |
| ChatGPT 未提供结构化问答工具 | 用普通中文问句询问类型；用户可直接输入现有类型或“都不是，新建配图类型” |
| 通过 OpenAI API 自建客户端 | 只有应用实际注册并实现了问答函数 / MCP 工具才调用；应用负责展示问题、等待答案和返回结果。单独安装本 skill 不会创建按钮或注册问答函数 |

若运行指令把 `request_user_input` 限制为可选澄清，而本次缺失信息必须等待用户回答，改用普通中文问句，不绕过工具约定。不要为测试或演示问答而触发用户当前没有请求的制作流程。

## 能力告知与主问题

先用简短中文说明能力，再发起问题：

> 当前可以制作合作公告、活动预告 / 回顾 / 嘉宾金句、安全周报 / 阶段汇总、安全事件分析、产品更新和研究观点配图，也支持人物透明 PNG、单蓝 / 单橙 / 蓝橙 / 黑白灰风格、同项目的静态与动态配图、官网 / 落地页 / 邮件产品营销动图，以及参考图贡献、skill 共建和合成参数提炼。

### Codex `request_user_input` 参数示例

以下是当前约定下的工具**参数对象**，不是终端命令、API 请求、工具注册 schema 或给用户阅读的文字。实际执行时通过当前宿主提供的工具通道调用，不能只把 JSON 发给用户并宣称已完成提问。

```json
{
  "questions": [
    {
      "header": "内容类型",
      "id": "content_family",
      "question": "你这次希望制作哪一类 BlockSec 内容营销素材？",
      "options": [
        {
          "label": "已有内容配图（推荐）",
          "description": "合作、活动、安全周报、事件分析、产品更新或研究观点的静态 / 动态配图。"
        },
        {
          "label": "素材处理与参考共建",
          "description": "人物抠图、参考图分析或独立产品演示需求。"
        },
        {
          "label": "都不是，新建配图类型",
          "description": "描述新的帖子类型、用途与平台要求，再确定参考素材和制作规格。"
        }
      ]
    }
  ]
}
```

遵守实际工具约定：一次 1–3 个问题，每个问题含 `header`、稳定 `id`、单句 `question` 与 2–3 个带 `label` / `description` 的选项；标题保持简短。工具自己提供 Other / 自由输入时，不手动追加第四项。“都不是，新建配图类型”是任务语义选项，仍作为第三项保留。

用户首条消息已指定类型时，把对应组放在首位作为推荐选项，保留“新建类型”，并在确认问题中引用已给出的类型。工具只有三个选项时按上述三组呈现；具体子类型优先从已有请求判断，真正不明确时再补充一轮，而不是默认第一组选项等于某个模板。

直接读取工具的实际返回值，通过稳定问题 ID 和回答文本理解选择。取消、空答案或工具失败不是“已选择第一项”；不把表单提交按钮、模拟输出或 JSON 参数当成用户回答。

### 普通对话回退

能力告知仍保留。随后用一个自由回答的中文问句，不复制选择卡片的编号菜单，也不向用户展示 JSON：

> 这次你想做什么类型的配图或动图？也可以直接说“都不是，新建配图类型”，再描述希望发布的帖子。

已有明确类型时使用简短确认，例如：

> 这次按你提到的 Partnership 合作公告继续制作，可以吗？

没有收到必要的用户回答时停在提问环节，不开始生成成品。不要把沉默或超时当成确认。

### 新类型需求补充

对必须自由描述的帖子用途、合作方 / 产品和特殊平台要求，优先使用普通中文问句收集，而不是虚构工具的自由文本字段：

> 请简单描述这条帖子的类型和用途、涉及的合作方 / 嘉宾 / 产品，以及准备发布的平台；有特殊的画幅、文件格式或时长要求也可以一起说明。

参考图、视频与文件上传建议通过正常对话提出。`request_user_input` 只收集文本选择，不把“请上传图片 / 截图 / 视频”写成它的问题；用户回到当前窗口附文件后再读取分析。

## 选择后的处理

### 现有内容类型配图

确认用户要制作的具体内容类型：Partnership、活动、安全周报、事件分析、产品更新或研究观点。根据 [content-types.md](content-types.md) 映射到底层模板，再询问或读取必要的文案、Logo、人物、截图和参考图。若用户已经给出足够信息，继续制作，不重复问技术参数。

### 动图 / 参考图 / 素材处理

根据用户补充的目标分流：

- 合作海报背景网格循环：读取 [static-to-motion.md](static-to-motion.md)，使用 `/animate-cover`。
- 官网 / 落地页 / 邮件中的产品动画：读取 [product-motion.md](product-motion.md)，路由到已安装的 `$carrot`。
- 参考贡献与 skill 共建：读取 [reference-analysis.md](reference-analysis.md)，使用 `/analyze-reference`。直接调用者的用途是贡献候选，首次确认沿用此目标，不额外要求改成出图请求；只分析时尊重其项目级范围。
- 嘉宾照片透明 PNG：使用 `/speaker-cutout`。
- 已明确的活动金句或概要：分别使用 `/speaker-quote` 或 `/seminar-summary`。

### 都不是，新建配图类型

不要立刻选择最相近的旧模板并开始制作。先用一轮简短问题收集“帖子用途 + 合作方 / 嘉宾 / 产品 + 平台”，再补充真正缺失的文案和素材。不把下列字段变成长问卷；用户没有尺寸、时长或文件偏好时按已知用途推荐，已有字段不重复询问：

- 帖子或栏目类型：希望发布什么内容，长期栏目还是一次性活动。
- 主要用途：宣布、预热、复盘、教育、转化、导流、品牌曝光或其他目标。
- 合作方 / 嘉宾 / 产品：名称、身份、是否需要 Logo / 人物 / UI。
- 发布平台：LinkedIn、X、官网、邮件或其他渠道。
- 平台要求：横竖比例、像素尺寸、文件格式、时长、是否需要 GIF / MP4、是否需要无声循环。
- 文案与事实：标题、摘要、日期、数字、CTA，以及哪些文字必须逐字保留。
- 素材：正式 Logo、人物照片、截图、底图、参考图、视频或链接。
- 风格方向：纯黑、蓝橙、浅色，或希望参考的视觉特征。

明确建议用户提供一张参考图，用来分析版式、字体层级、素材位置、留白和动静分层。参考图只作为视觉研究资料，不自动复制第三方 Logo、文案、人物、二维码、独特插画或具体事实。

如果是动图或视频参考，建议用户按以下方式准备素材：

1. 复制原始帖子的公开链接。
2. X 图片 / GIF / 视频：将 X 帖子链接粘贴到 [x-downloader.com](https://x-downloader.com/en/)。LinkedIn 视频：将 LinkedIn 视频帖子链接粘贴到 [Taplio LinkedIn Video Downloader](https://taplio.com/linkedin-video-downloader)。LinkedIn 静态图片：直接保存原图；Taplio 是视频下载入口，不承诺能下载图片。
3. 下载文件到本地。
4. 回到当前窗口，将下载的图片、GIF 或视频直接上传给 AI，并说明希望参考的版式或动效。

已有文件直接接收，不重复下载。不自动替用户上传文件到第三方下载站，也不要求提供登录凭证。

## 一次对话的状态规则

- “首次调用”按当前对话计算，不按本次请求中包含几个子指令计算。维护 skill 文档不触发 onboarding；用户使用本包子指令完成实际内容任务时才触发。
- 以实际用户回答或既有明确确认判断首次引导是否完成；仅发出问题、工具失败或未收到回答不等于完成。确实需要用户选择时等待普通对话回答；仅为可选澄清且工具返回空答案时按宿主指令处理，不重复调用。状态从当前对话的消息判断，不创建跨对话用户档案或修改共享技能文件。
- 用户在同一对话后续从 `/speaker-quote` 切换到 `/animate-cover`，直接进入对应流程；用户明确切换已有类型时按其请求路由；只有说“新建类型”时才进入新类型需求收集。
- 可以先读取技能说明和能力索引以准确介绍功能，但首次类型选择前不启动成品生成或修改用户项目。用户补充答案后，复用首条消息中已提供的素材。
- 新类型明确后，先整理当前项目的用途、画幅、素材和版式规格，再制作首版；现有模板能覆盖时优先复用。用户希望共同维护或让后续用户复用时，进入 `/analyze-reference` 共建流程；普通新建配图需求仍保持项目级制作。
- 这套 onboarding 不要求用户先学习模板 ID、字体名称、帧率或渲染工具。
