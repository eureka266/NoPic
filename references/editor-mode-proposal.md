# Blocksec内容营销配图：可选微调模式方案

评估日期：2026-10-14（香港时间）。状态：localhost 编辑器仍为产品与技术建议；模板参数持久化基础现已实现，详见 [模板名称与参数](template-parameters.md)。所有改动仅在工作区，不同步技能安装目录。

## 已确认的使用场景

最终使用者是内容运营或 COO 本人；目前通常通过向 ChatGPT 提出修改意见来调整配图。自然语言反馈是已经形成的使用习惯。操作频率、常见修改案例以及他们是否具备本机 agent 环境尚未确认，不推断他们愿意学习设计软件。

产品优先支持“给材料 → 看第一版 → 提修改意见 → 看新版”的完整闭环。可选页面用来处理用户希望亲手确定的位置、比例与换行，用户打开后也能返回对话继续修改同一项目。

## 结论与价值判断

默认由 agent 按类型选择固定模板，完成素材准备、文案排版、出图和视觉检查。成品交付后，用户可以继续对话修改；未来可选择打开本机微调页面。无需在开始时强迫用户选择方式。

可选页面的价值是减少“再往右一点 / 名字再大一点”的沟通往返，并让运营或 COO 在 agent 完成第一版后亲手确认视觉细节。基于已确认的对话修改习惯，默认流程应优先把自然语言修改做完整；页面作为随时可选的辅助入口，不能成为完成配图的必经步骤。开发优先级仍需用实际修改案例和频率验证。

产品定位：基于已生成品牌模板的成品微调工具。首版不引入钢笔、节点、布尔运算、滤镜等专业绘图操作。品牌模板仍是默认起点。

## 最小用户流程

1. 用户给材料，agent 按固定模板交付 PNG 和可复用项目。
2. 用户可以继续说“只改标题”“保留其他内容，人物往右移一点”等修改意见；agent 读取同一项目并应用修改。计划中的页面入口在成品旁标为“自己微调”，用户明确选择后才启动本机服务并打开对应项目。
3. 页面先显示当前成品。左侧用“标题、说明、人物、BlockSec Logo、合作方 Logo、背景”等业务名称；中心显示画布；右侧显示选中对象的操作。
4. 用户点文字修改内容、拖动位置、拖拽角点等比例缩放素材，必要时更换已有素材。
5. 用户保存并导出。保存后的项目可由 agent 继续修改，人工位置调整不被恢复成默认模板。

首版默认展示：改文字、移动、等比例缩放、更换素材、撤销与导出。文字字号/对齐、吸附、恢复模板和另存副本放在选中对象的相关操作里；从已有图库切背景可放在背景面板中。前后层级调整按实际遮挡案例决定是否纳入首版，不把大量工具同时铺到页面上。

默认锁住背景移动；Logo 保留原色与比例。提供明确的解锁位置操作，不通过手工调色改变 Logo。无需暴露 JSON、坐标矩阵、字体文件路径或图层技术术语。超出画布、文字溢出、素材遮挡应在相关对象附近给出中文提示，保留原内容。

换素材和背景须延续 AGENTS.md：保留原文件、不覆盖旧预设、只在明确要求时生成新底图。即使图像包含复杂插画，也只把独立人物/截图/背景作为位图对象，不承诺编辑扁平 PNG 内部的所有元素。

## Storytold 项目核查

用户提供的是 GitHub 组织入口（末尾带中文句号），评估对象为该组织的 VectorCraft。

- 官方介绍：浏览器版与原生桌面版，采用 Rust、egui/eframe、WASM；项目目标包括复现 Illustrator 界面。已公开的能力包括位图/文字、移动缩放、图层、对齐、撤销/重做、原生 JSON、SVG/PNG 导出。
- README 将成熟度标注为 alpha；不据此承诺适用于非设计用户的生产稳定性。
- 控制协议包含 document.inspect、engine.execute、ui.pointer、ui.render、app.save 和 app.export 等操作，可参考其 agent 与 UI 共用模型的思路。桌面版有本地 TCP 控制服务，vectorcraft-cli 提供 MCP；浏览器版源代码明确说明没有 TCP 控制服务，打开文件使用浏览器选择器，保存/导出触发下载。因此本机项目的自动加载、回写配置及 agent 接续仍需额外集成。
- Cargo.toml 声明 MIT OR Apache-2.0 双许可。若实施时复制源文件，应核对具体文件及依赖许可，保留所需的版权和许可声明，并记录上游版本。仓库另说明打包素材各有许可，修改版需移除受其品牌许可限制的 ArtCraft 标记，不把代码许可视为品牌授权。

可借鉴：统一文档模型、用元素 ID 做精确操作、撤销历史、选中态、拖拽和对齐。

不建议直接搬入：完整工具栏、专业矢量绘图工具、全部桌面/Rust/WASM 构建链。它们会扩大本项目的维护面，且不能自动解决非设计用户的理解成本。

## 与现有 skill 的兼容设计

已实现基础：`assets/templates/` 保存六套按用途与版式命名的默认模板；两个渲染脚本读取这些参数。新出图项目的 `content.json` 保存完整 `template` 副本、易辨识的 `template_id` 和 `layer_overrides`。位置和大小调整可通过 `--layer` 完成，改文案时保留，使用 `--reset-layer` 可恢复单元素默认值。参数采用原始画布的整数像素，以保持现有 Pillow 排版与出图一致。

旧 `layout` 字段和文案/素材字段仍兼容，配置在成功渲染时升级到 schema_version 2；已保存项目后续从自己的模板副本读取。活动概要要点拥有稳定 ID，覆盖随相同要点保留。详见 [模板名称与参数](template-parameters.md)。

待实现：轻量页面的选择、拖拽与文字表单、本机服务、保存冲突处理及交付时的页面入口。页面须操作同一份模板副本与覆盖，不再维护另一套独立排版数据。图片容纳框与实际可见范围应在页面中区分，背景默认锁定。

## 实现路径建议

优先使用轻量页面、本机服务和当前 Python 出图引擎。页面显示权威渲染预览并叠加选择框/拖拽控件；拖动时及时显示位置反馈，释放或短暂防抖后请求渲染。预览与导出共用字体、换行、文字强调、透明素材裁边、区域适配规则，减少浏览器与 Pillow 双重排版产生的偏差。

Fabric.js 可以作为对象选择、拖拽、缩放、分组、JSON 持久化和导出的候选组件；它是画布库，不是现成的面向运营的编辑器。是否引入，应通过原型确认收益：若选用其文字渲染，必须验证中文字体、换行、金句强调和最终导出的一致性。不要同时长期维护两套互不一致的模板/排版系统。

本机服务只监听 loopback，使用系统分配或可用端口；浏览器关闭后有明确停止方式。Web 页面上传/替换素材后保存到当前项目；不要把用户电脑的任意路径作为公共静态目录。文档写入采用修订号，agent 与页面同时保存时提示冲突，防止最后一次写入静默覆盖另一方。另存副本后导出，失败时保留上一份成品。

建议先拿一个真实高频模板验证（暂建议嘉宾金句，待确认实际使用频率）。成功后复用同一模型覆盖合作图和活动概要。第一阶段不要承诺多人在线协作、账号权限或云端素材库。

## 完成标准

- 不熟悉设计工具的同事无需解释即可找到文案、人物与 Logo，并完成改字、移动、缩放、导出。
- 同一份配置，页面预览与下载 PNG 的换行、字体、位置一致；缩放显示不改变原始导出尺寸。
- 无需打开编辑器，用户能通过连续自然语言反馈完成局部修改并得到新版本；明确范围外的文案、背景、素材和位置保持不变。
- 改标题后仍保留人物位置；更换透明人物后保持比例；恢复模板能够撤销。
- 旧 content.json 可打开和渲染，新配置回到 agent 流程后保留手工修改。
- 连续撤销、关闭后重开、替换素材、超长中英文、导出失败均有可理解结果；不存在只在页面里生效而未持久化的修改。

后续验证：每周频次、最近几张真实配图中最常修改的部分、使用者能否在本机运行 agent。用户希望通过 localhost 微调，但已确认的 ChatGPT 使用习惯并不等于已具备本机运行环境；页面的启动、项目加载与保存应由工具处理，不能把终端命令和文件配置交给内容运营或 COO。若真实使用环境无法运行本机工具，再讨论共享网页入口，避免提前扩大部署范围。
