# 一张一张补齐 README 示例

面向使用者的示例制作路径。每次只准备当前这一张的材料，出图后用中文反馈；确认完成后再推进下一张。完整海报用实际合成成品展示，底图缩略图始终注明“底图”，不作为已完成示例。

标题：填写允许展示的标题

用户没有标题和说明、只希望放双方 Logo 时，使用已有极简双 Logo 模板。未允许公开展示时，可以先制作私人项目，不能自动将素材和成品写入共享 README。

agent 接收本步材料后，检查 Logo 与文案，调用实际合成脚本生成 PNG 和完整项目，并查看成品。用户确认后保存到 `assets/examples/<example-id>/`，登记 [示例状态](../assets/examples/index.json)，在 README 用相对路径缩略图链接原图。后续继续保留原图和配置，不覆盖其他例子。

## 当前下一步：活动预告

这一步只需要活动名、明确日期与时区、主题和允许用于示例的说明。若想展示嘉宾或主办方，再提供对应正式素材；不要求活动预告必须有人物。用户确认本次素材可用于示例后，制作首版，核对实际成品并补进 README。

## agent 每一步只做这些事

1. 读取示例索引和已提供素材，只指出本张实际缺少的材料。包内有合适正式 Logo 或字体时不重复索取。
2. 用户说明的类型与风格优先；缺少偏好时选已有默认模板和底图，不为“更适合”重生成背景。
3. 制作完整成品，核对准确文字、Logo 保真、构图和可读性，再给用户预览。依赖不可用时说明实际阻碍，不以待制作路径替代成品。
4. 允许用于 README 且完成视觉检查后再登记成品，保留来源与示例授权记录；公开引用的素材路径均相对于技能目录，私人素材只留本次项目。
5. 完成后告诉用户下一张具体需要什么，避免一开始列出所有模板的资料清单。对剩余步骤的文件不预先标为完成。

## README 的展示规则

- `pending`：缺少材料或还未制作；只写下一步，不展示假成品。
- `draft`：已制作预览，但仍需核对或未获示例使用授权；明确标为草稿。
- `ready`：实际输出存在、视觉检查通过、允许用于示例；可放入 README。
- 图片保持小尺寸、相对路径和点击原图，横版约 160–240px，竖版约 100–140px。
- 首页先展示已完成案例；底图参考放进可折叠区域，完整底图库保留在 [详细手册](user-manual.md)。
