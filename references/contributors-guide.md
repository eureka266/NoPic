# Blocksec内容营销配图：用户共建指南

这份指南面向希望共同改进配图效果的同事。你只需提供参考、用途和修改意见，AI 负责整理设计规格与贡献文件；不需要手动修改 JSON、模板或脚本。

日常使用现有类型出图，可以直接提出制作需求。希望把优秀参考、改进方案或新类型留给后续使用者时，使用 `/analyze-reference` 进入共建。

## 可以贡献什么

| 贡献方向 | 你可以提供的内容 |
| --- | --- |
| 现有类型的新视觉方案 | 更好的合作公告、活动、安全周报、事件分析、产品更新或研究观点参考 |
| 新配图类型 | 帖子用途、平台、核心信息和已有素材，例如某个长期栏目 |
| 排版改进 | 希望调整的标题层级、留白、Logo 比例、人物位置或说明文字 |
| 底图与素材 | 参考底图、允许使用的正式 Logo、人物照片、截图或已生成的背景 |
| 动效参考 | 希望借鉴的循环、文字与背景关系，以及原始 GIF / 视频 |
| 使用问题 | 实际成品、复现用文案和“哪里不符合预期”的说明 |

仅希望修改本次图片时，直接说“只改这张图，不加入共享库”；AI 会保持项目级制作。没有参考图时也可以贡献明确的改进意见，不必先寻找参考才能开始。

## 第一步：说明用途与贡献目标

上传参考图或现有成品，并用中文描述想改善什么、用于什么内容与平台。首次调用时会先完成一次能力介绍和类型选择；已经说明要共建的，继续沿用这个目标。

贡献现有类型的参考：

```text
/analyze-reference
我想贡献一套适合 BlockSec 安全周报的配图参考。
这组图的标题层级和日期区域很清楚，希望借鉴它的阅读顺序，用于领英 / X。
请提炼成可审阅的方案，验证后加入共享参考库，保留原有方案。
```

提出新类型：

```text
/analyze-reference
都不是，新建配图类型。
我想为一个新的长期栏目制作配图，主要用于领英 / X。
栏目用途：这里填写想传达的信息
涉及的合作方 / 嘉宾 / 产品：这里填写，未涉及则写无
必须保留的信息：这里填写
请整理新类型的建议和验证样图，作为 skill 的共建候选。
```

提出使用问题：

```text
/analyze-reference
我想把这次发现的问题修正到 skill 中。
附图是当前成品；正文偏小，换成长一点的标题后又遮住了 Logo。
请定位影响这类图片的规则，给出修正后的可审阅结果，保留其他类型的排版。
```

## 第二步：提供已有资料和参考

优先提供原始图片、准确文案、正式 Logo 和真实产品截图。说明希望借鉴的部分，例如字体层级、布局、底图材质、素材位置或动效；参考中有哪些地方不喜欢也可以直接说。

有特殊的平台比例、文件格式或时长要求时一起说明；没有偏好时由 AI 推荐，用户无需学习帧率、坐标或渲染术语。

参考来源是 X 图片 / GIF / 视频时，可把原帖子链接粘贴到 [x-downloader.com](https://x-downloader.com/en/) 下载。LinkedIn 视频可使用 [Taplio LinkedIn Video Downloader](https://taplio.com/linkedin-video-downloader)，静态图直接保存原图。下载后回到当前窗口上传文件；已经有文件时直接上传。

参考用于设计拆解。新图仍使用本次确认的文字、BlockSec 正式 Logo 和可用素材；参考图的合作关系、数字、身份与品牌标识不带入新图。

## 第三步：查看 AI 整理的贡献

AI 会给出：

- 适合的内容类型，以及改进原类型还是新增一种形式。
- 字体候选、字号层级、图层关系、相对位置和底图 image_gen 提示词。
- 当前合成器能实现的参数，以及仍需补素材或扩展能力的部分。
- 适用时的验证样图 / 动图，并说明相较原版改变了什么。
- 贡献名称、文件位置、拟修改范围和验证状态。

仅凭位图不能确定字体时会标注推断；提炼了提示词也不等于已经生成底图。缺少正式素材或动画能力时，应看到清楚的限制说明，不应看到虚假的完成结果。

## 第四步：用普通语言反馈或确认采用

你可以直接说：

```text
标题可以更大，说明再短一些，Logo 的比例保持不动。
```

```text
采用这套视觉规则，加入共享参考库作为活动配图的新方案。
保留现有默认模板，不替换旧方案。
```

希望一次授权后自动推进，可以在开头说“整理、验证并自动加入共享参考库”。AI 会按已给授权推进，不重复要求同一确认；尚未通过的验证仍会如实说明。

## 第五步：识别贡献状态

| 显示状态 | 意味着什么 | 后续如何使用 |
| --- | --- | --- |
| 候选草稿 `draft` | 分析和设计建议已整理，尚未审核 / 验证 | 继续反馈和完善 |
| 已确认规格 `reviewed-spec` | 设计已采用，实际渲染仍有待验证 | 可作为明确选择的设计参考，不能当作现成模板 |
| 已验证可复用 `ready` | 所需配置、素材、渲染和视觉检查已通过，且已获采用授权 | 可指定该方案用于后续出图 |

采用确认不会把未验证的规格直接变成 `ready`。新方案使用独立名称和版本，原有项目保留自己的模板副本。参考库是否已有可用贡献，以真实索引为准。

## 第六步：让团队获得更新

本地贡献入库后，AI 会按维护后的提醒流程准备候选 ZIP、变更说明和文件清单，再询问是否更新上传到 Blocksec 团队空间。已有明确的发布授权时不重复询问；普通出图不触发发布。

建议采用以下团队分工。这是协作建议，不代表工作区已经配置了这些权限：

| 分工 | 负责什么 |
| --- | --- |
| 贡献者 | 提供参考、用途和反馈，审核自己的设计方案 |
| 维护者 | 在团队维护的源码中合并贡献，检查兼容性和验证结果 |
| 有发布权限的同事 | 确认目标工作区与现有 skill，上传更新并记录版本说明 |

大家在不同本地副本中完成贡献，不会自动修改所有人的版本。团队应约定一个维护源，由维护者汇总变更；工作区中是否能编辑 / 上传，以实际账号权限和管理入口为准。没有源码访问权时，AI 可以先准备贡献文件，交给维护者合并，不要求所有同事获得发布权限。

发布后应核对目标 skill、更新结果，并在团队环境做一次代表性的实际出图；只有上传成功后才说明团队版本已更新。Carrot、HyperFrames、字体、素材路径和知识库等依赖需要分别验证，不会因为分享 skill 就自动准备好。

## 复用已经验证的贡献

可以这样询问和制作：

```text
使用 $blocksec-social-cover，列出当前安全周报类型已验证可复用的参考方案。
```

```text
使用 $blocksec-social-cover，按“这里填写已验证的方案名称”制作本期安全周报。
下面是本期确认的标题、日期范围和摘要，保留正式 Logo。
```

如果找不到该方案，让维护者确认它是否已入库、发布，以及当前使用的是哪一版 skill；不能用一个不存在的名称当作已加载模板。
