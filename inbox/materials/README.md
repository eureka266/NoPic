# 用户原始素材收件目录

这里统一保留用户通过聊天、拖拽或本地路径交给 agent 的原始素材：正式 Logo、人物照片、产品截图、确认文案和风格参考。内容运营或 COO 可以直接把文件拖到本目录，也可以在聊天里发送，由 agent 收集。

## 保存方式

- 直接拖入的文件保持原文件名，不需要用户整理。agent 处理时可复制到有意义的批次目录，保留已有原文件。
- agent 从聊天附件或其他路径收集的文件，保存在 `YYYY-MM-DD-用途/`，日期使用香港时间，例如 `2026-10-14-template-examples/`（模板效果图示例）。同批次原文件保留原名，遇到同名不同内容则另建有意义的子目录或新批次，不覆盖原文件。
- 批次内使用 `materials.json` 记录实际文件名、中文显示名称、素材类型（logo / portrait / screenshot / copy / reference / other）、用途、来源与是否仅供参考。只登记实际收到的文件，不把预期文件登记为已收到。
- 示例素材用途中注明 `template-example`，正文和姓名采用用户提供并允许用于示例的材料。未经确认的照片、客户信息或业务文案不自动加入可对外分发的示例资产。
- 原照片与抠图分开保存。裁切、去背景、格式转换只在当前制作项目或 `assets/examples/` 的项目副本中完成，不修改收件目录原文件。
- 每个可复用出图项目仍保存自己实际使用的素材副本，避免移动原始素材后项目失效。

背景原图延续现有规则，先保存到相邻的 `inbox/backgrounds/`。不要迁移或覆盖现有背景文件。需要正式入库时，背景复制到 `assets/backgrounds/` 并更新索引；正式 BlockSec Logo 的使用副本放入 `assets/logos/`，原文件仍留在收件目录。参考海报与可直接使用的背景分开标识。

## 制作 README 效果图所需素材

- 正式 BlockSec Logo：优先透明 PNG，建议深底用白色版；如需浅色示例，再提供深色/彩色版。SVG 也可作为原始文件保留，渲染时使用导出的副本。
- 一个合作方的正式 Logo：用于两套合作公告版式。
- 一张允许用于示例的嘉宾原照片，以及姓名、职位/机构和示例金句。若另有透明抠图，可以一起提供，但原照片仍保留。
- 一个产品截图或已有插图：用于文章封面右侧主视觉，可选。
- 活动概要的确认标题与要点，或明确允许使用虚构演示文案。演示文案需在效果图说明中标明，不能冒充真实嘉宾发言或合作公告。

完整模板列表和效果图完成状态见包根目录 `README.md`。
