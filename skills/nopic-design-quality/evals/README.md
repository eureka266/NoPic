# 场景评测

这些场景检查提示词的判断与执行边界，不证明审美质量、模型稳定性或真实页面功能全面通过。

## 执行

在 NoPic 源码仓库根目录执行。案例中的 `artifacts` 路径相对于仓库根目录；截图与组织规范由具体测试任务提供，不随方法论 skill 分发。从已安装副本评测时，明确提供源码仓库路径；输入不可用的案例记为未完成。

1. 对 `SKILL.md` 运行 skill-creator 自带的 `quick_validate.py`，检查格式与名称。它不能验证视觉判断。
2. 读取 `cases.json`。向独立执行者提供当前 skill、每个案例的 `request` 和 `artifacts`；不要提前提供 `checks` 或预期结论。案例之间按独立任务处理，无需写文件或操作外部应用。
3. 允许只读对应的原始公开素材。截图场景必须实际打开截图；其余场景中的检查记录和配置摘录是提供的输入，不能声称自己执行了测量或浏览。
4. 每个案例返回实际回答和使用过的证据。由评估者对照 `checks` 逐项判断，任一要求违背即失败；能力不足或材料无法读取时记录未完成，不能算通过。
5. 出现问题后缩小修正提示词，再重跑受影响场景。最终报告记录版本、执行日期、评测者、通过 / 失败 / 未完成数和局限。

这些是人工或模型行为评测，不是通过关键词匹配的自动测试。根目录 Python 回归测试另行运行：

```bash
python3 -m unittest discover -s tests -v
```

结果可记录到 `results-YYYY-MM-DD.md`；不把私人素材、原始客户数据或会话历史提交到仓库。
