# 有来源的设计基线

设计基线记录“这次检查以什么为准”。它不是要求用户先完成的新品牌手册，也不要求安装某个设计系统。

## 读取顺序与冲突

先读取用户当前要求、目标项目的正式规范和已确认团队记录，再读已有 tokens、组件、品牌包和对应模板。代码表示当前实现，不自动等于官方品牌规范。参考作品表示一个案例，不自动等于团队共识。

- 同一产品的已确认规则适用时优先沿用。
- 上层规范不明确时，既有实现可作为“项目惯例”检查局部一致性，但不能写成正式规范。
- 不同来源冲突时记录冲突和影响；不悄悄混合字号、圆角或颜色体系。能完成的其他检查继续进行。
- 值缺失不构成视觉失败：评价可见结果，并把无法验证的“是否符合正式规范”列为待验证。
- 颜色、字体或间距的替代建议需写清当前依据；不因缺值创建假的官方数字。

## 按需提取的基线表

只记录当前任务有用的项，保存在 QC 报告中即可；没有用户要求时不改共享规范。

| 领域 | 应记录的内容 | 常见证据 |
| --- | --- | --- |
| 品牌身份 | 完整标识 / 独立图标、背景适用性、产品归属、合作方版本 | 正式 Logo 索引、品牌包 |
| 色彩角色 | 背景、表面、主次文字、品牌强调、操作、风险、错误、成功 | tokens、正式规范、已确认团队记录 |
| 字体层级 | 中英文字体、真实加载、标题 / 正文 / 标签 / 数字、字重、行距 | 字体资源、tokens、模板 |
| 布局 | 页面容器、网格、间距级差、对齐、断点、文本安全区 | 组件、模板、正式设计稿 |
| 组件与状态 | 主次操作、输入、表格、选中、禁用、加载、错误、空态 | 现有组件及运行状态 |
| 图片处理 | 裁切、人物、截图、底图复用、Logo 视觉重量 | 项目配置、源素材、代表作品 |

每项采用 `规则或值 / 来源 / 适用范围 / 状态` 的方式记录。状态区分：正式规范、团队已确认、项目惯例、候选建议、未知。候选建议不能用作强制否决标准。

示意：

- `深底使用组织白色完整 Logo / 当前项目 Logo 索引 / 组织 深底配图 / 项目基线`。
- `研究封面标题行距 / 未找到有效来源 / 中文研究封面 / 未知`。

以上只说明记录方式。必须以目标项目中实际可读的文件和版本核实，不机械沿用示意。

## 方法与组织资料的边界

实际颜色、字体、尺寸、素材索引和团队记录以当前组织包为准。方法论不指定某个组织的色值或字体。没有适用的正式来源时保持未知，不将缺值本身当成视觉缺陷。

公开占位演示只能验证工程行为；真实案例的展示授权也不等于团队审美认可、合作关系核实或素材再分发许可。
