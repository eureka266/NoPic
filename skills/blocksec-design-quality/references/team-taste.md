# 团队审美记录与校准

当前状态：**尚无本 skill 收录的团队已确认记录**。本文件的字段和示例文字是记录方法，不是团队共识。不得把现有成图仅因存在或曾用于 README 就自动认定为审美标准。

## 哪些信息值得记录

用户要求沉淀时，从真实作品与反馈提炼：我们认可或不认可哪一点、为什么、在哪些情况下适用。先读上下文，避免把任务限制误解为审美偏好。

- “这张图背景太复杂”可能与当前标题长度有关，不等于所有背景都要纯色。
- “合作方 Logo 小一点”可能为平衡两个形态，不等于合作方永远次要。
- “更有科技感”需要结合具体作品解释成色彩、材质、密度、图形关系或排版的变化，不能直接写成加网格。

没有示例也能按基线开展工作；需要校准时，优先收集约三张团队认可的作品和两张不认可的作品，每张只需一句理由。数量是建议，不是启动门槛。UI 与配图分别收集，允许按不同内容类型形成不同方向。

## 单条记录

每条记录保持简短；只有需要时创建实际记录文件，不预建空条目。

- **ID 与名称**：稳定标识和容易理解的方向名称。
- **状态**：候选 / 已确认 / 已停用。AI 推断默认候选；只有用户或指定维护者明确认可规则或代表性后才能写为已确认。普通导出不等于确认。
- **范围**：品牌或产品、UI / 网页 / 配图、内容类型、语言、画幅或场景。局部偏好不升级为全局规则。
- **代表证据**：真实文件路径或截图、版本，以及可访问的原反馈。
- **判断与理由**：具体认可或避免什么，如何帮助任务或传播。
- **适用条件与例外**：何时沿用，何时不应套用。
- **复用能力**：可编辑项目 / 已验证模板 / 仅方向参考，附真实路径。未经渲染验证不得写成可直接使用。
- **确认信息**：明确确认人、香港日期和原话依据；未知字段留空，不猜测。

原图和原始反馈保留。用户要求更新时新增版本或保留变更记录；“已停用”保留历史依据，避免重新引入旧规则。

## 首页与制作的共同读取约定

- 首页“团队精选”默认只展示已确认且有真实代表图的记录；候选如需展示，清楚标注。
- 同时展示作品、简短理由与适用场景。展示不应只剩“高级、简洁、科技感”标签。
- “沿用这个方案”只关联实际可用项目或已验证模板；外部参考或分析记录使用“参考这个方向”。
- 制作时按当前品牌、任务和内容类型匹配同一条记录，沿用适用规则；用户当次明确要求优先。
- 文件存到本地不代表已经同步给团队。跨项目共享、品牌包扩展、首页接入和同步需要实际实现，本 skill 不假装已有这些能力。
